# Tests

Memory rule: never run sims in parallel, never run more than one test command at once, give long commands a timeout.

- `node tests/all.js` runs part A and `node tests/all.js b` runs part B of the **quick set** (split so each half stays well under the 5-minute cap; run both, one after the other): unit tests and fixture-based feature tests, one child at a time with a heap cap (a minute or two). S7a adds `heat` (the heat table), `events` (the unforced lightning decision over a year of pressure, no sim) and `discovery` (witness, tinker, loss and rediscovery, hearth, save round-trip, determinism). S7b adds `chain` (the clay -> charcoal -> copper chain: table, stations, both heat-4 routes, loss, pick, workshop, jars, determinism) and `property6` (the competent bot, fixture-to-fixture segments of <= 10 game days; the single-run `bots/chainrun` is --full only and is for the balance pass).
- `node tests/all.js --full` also runs the multi-seed, multi-year bots (`bots/*`, `bots/k6 --year`). Use once, at the end of a phase. `fanOut` in `bots/lib.js` runs `SIM_JOBS` (default 2) children at once.
- Also run `node tools/build.js`, then `node tools/ui_smoke.js`, `node tools/ui_shots20.js`, `node tools/ui_smoke_p7.js` and `node tools/ui_smoke_fpv.js`, one after another (one Chromium at a time; each is under five minutes) before finishing a stage.
- **Small change?** Run only `node tools/build.js` and `node tools/check.js` (about 2 s: the game loads with no console errors, plus one optional selector/text or `--eval` assertion), and the unit test for the module you touched. Never the quick set or the smoke scripts for a small change; those are for the end of a stage.

## Fixtures
`tools/make_fixtures.js` plays one seed (7) once and writes saves to `tests/fixtures/*.json`: `start`, `settled` (day ~24), `prewinter`, `midwinter`, `year2`, `hut` (a roofed shelter with beds, built by the scripted shelter player), and from S6 `mine` (a stair and tunnel in soft rock east of camp with an exposed malachite face and a hidden pocket behind it, scripted from `settled`) and `ores` (12 flint, 12 clay, 12 malachite in the stockpile), and from S7a `fire` (derived from `prewinter`: exactly two villagers hold FIRE_TENDING, a lit hearth in camp with fuel, 10 logs and 20 sticks in stock, day 74). A fixture with `from:` is derived from a saved one by a `prep(sim)` edit, so it costs nothing; `carveMine` returns its coordinates. A test does `const sim = loadFixture("settled")` (`tests/fixture.js`) and runs only the window it needs (a few game days). `loadFixture` regenerates the whole set when a file is missing or its save version is old, so after bumping `SAVE_VERSION` the next test run takes one long run and rewrites them; commit the new files. To add a fixture, add an entry to `FIXTURES` in the tool.

A feature test: load a fixture, issue commands with `sim.apply`, step a bounded window, assert the feature works. Balance is a best guess and is tuned later; do not tune with year-long runs.

S16 (endless world): fixtures were **regenerated** (the world itself changed: `rm tests/fixtures/*.json; node tools/make_fixtures.js`, one sequential run of about 10 s). S18b (clock rebase): fixtures were regenerated (the `settled` fixture is tick 36000; see the README "Clock rebase (6.18b)").
